# 开发模式：中文字符串与正则

## 背景

本项目是一个中文写作辅助工具，UI、文件名、内容大部分是中文。
正则表达式和字符串操作中容易忽略中文字符和 ASCII 字符的差异。

## 常见陷阱

### 1. 冒号（`:` vs `：`）
- 侧边栏显示名使用中文冒号（如 `第1章：标题`）
- 正则 `/:.*$/` 只匹配 ASCII `:`，在中文显示名中匹配失败
- 修复：用 `[:：]` 字符组同时匹配两种冒号

### 2. 文件名中的点号
- 文件名格式 `chapter-001.md`，点号参与 `localeCompare` 排序
- `.` < `a`，利用这点做插入命名（`chapter-001a.md`）

### 3. 数字表示（`1` vs `一`）
- 文件名用阿拉伯数字，显示名用中文数字
- 转换函数 `toChineseNum()` 在 `App.jsx` 和 `novelData.js` 中

### 4. window.prompt 提示文字
- 直接传中文字符串可以，不需要走 `t()` i18n

### 5. Edit 工具的 file_path
- 这是最容易忘的参数。调用 Edit 前先把 `file_path` 写好再写其他参数。

## 检查清单

修改任何涉及字符串匹配/替换的代码时：

1. 搜索用的字符是全角还是半角？
2. 正则字符组是否覆盖了中文对应字符？
3. 测试数据是否包含中文字符串？
4. 显示名、文件名、文件内容的字符编码是否一致？
