# 联网人设补全测试契约

最后更新：2026-07-11

## 目标

联网补全的验收不能只问“是否填出了内容”。测试应分别回答：

1. 路由是否把请求交给了合适的文化圈和来源；
2. 搜索、抓页是否取得**目标角色**的正文；
3. 结构化字段是否有正文证据，并且没有串作品、串角色或模型补写；
4. 改动是否在未参与调试的样本上仍然成立。

空字段是允许结果；无证据的字段和错误角色字段不是。

## 三层测试

| 层级 | 输入/产物 | 必须衡量的结果 |
|------|-----------|----------------|
| Replay 回归 | 固定查询、搜索结果、页面快照 | 查询构建、排序、解析、字段锚定不回归 |
| Live smoke | 少量代表角色，真实联网 | 路由、正确页面 Top-K、抓页可用性、延迟和站点变化 |
| Live acceptance | 完整且轮换的 roster | 端到端覆盖、字段证据正确率、文化圈/热度分层表现 |

日常开发先跑 Replay 和单作品 smoke；只有前两层通过才跑完整 live acceptance。

## 样本与标注

每个角色至少覆盖：文化圈、热度层级、同名风险、可接受来源、角色/作品别名、禁止串入词。参考标注必须独立维护，不以模型输出反推。

建议将 roster 分为：

- 开发集：允许针对失败做迭代；
- 回归集：保留已修复的典型事故；
- 隐藏验收集：不参与日常调参；
- 轮换集：从 pool 抽样，防止对固定名单过拟合。

## 指标与门槛

`pageLen >= 200` 只表示正文可能存在，不能代表正确页面。正确页面需结合作品/角色别名、标题、URL/来源和禁止词判断。

| 指标 | 定义 | 初始门槛 |
|------|------|----------|
| Coverage rate | 通过完整度与页面锚定的角色 / 全部角色 | ≥ 90% |
| Reference coverage rate | 有人工参考标注的角色 / 全部角色 | ≥ 80% |
| Reference accuracy rate | 已标注且端到端正确的角色 / 已标注角色 | ≥ 95% |
| Reference wrong-character count | 已标注样本中命中禁止串入词的数量 | 0 |
| Correct-page@3 | Top 3 中含正确角色页的比例 | 按文化圈单独记录 |

没有人工参考标注的角色不得计为“准确”；它们只参与 Coverage。验收通过必须同时满足三项比例门槛与已标注样本零串角色要求；随着参考集覆盖扩大，再将该门槛推广到全量样本。

## 可追溯报告

每次 live 运行至少保存：roster、查询、文化圈、来源顺序、Top-K、最终 URL/页面标题、正文长度、状态、耗时、代码版本、配置和代理环境。字段级结果应逐步补充 `sourceUrl` 和正文证据片段。

报告必须按文化圈、作品、热度层级和失败原因分组，并与上一份基线比较。总分提高但任一文化圈显著回归，或出现新的串角色，均不得判定通过。

## 失败定位

1. `resultCount=0`：文化圈、查询构建或来源选择；
2. 有结果但无正文：抓页、WAF、脏 URL 或来源故障；
3. 有长正文但错误页面：角色/作品消歧和排序；
4. 页面正确但字段为空：页面 parser 或提取提示；
5. 字段无证据或串角色：字段锚定、合并和拒绝规则。

修复必须先在对应层的最小样本复现，再按 Replay → smoke → 全量 acceptance 的顺序回归。
