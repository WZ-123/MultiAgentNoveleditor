# Codex 原生运行契约

更新：2026-10-19。实现入口：[会话服务](../src/main/codex-runtime/codexSessionService.js)、[任务范围解析](../src/main/codex-runtime/taskIntent.js)、[写作工具](../src/main/mcp/writingTools.js)、[审查任务](../src/main/codex-runtime/narrativeReviewJobs.js)、[审查账本](../src/main/codex-runtime/reviewLedger.js)。本文描述跨模块职责与当前实现；当前验证结果、历史失败及剩余限制分别见[审计报告](../artifacts/chat-chain-audit/report.md)和[缺陷清单](edge-cases.md)。功能存在或自动测试通过均不等于真实正文质量通过。

## 身份、路由和能力

novelId、conversationId、runId、taskId、attemptId及原生threadId/turnId各有独立用途。读取、批准、提交、报告和继续任务必须属于同一小说与任务；切页面不能挪用旧批准。同一项目的原生任务串行，同一对话不能并发发送。

项目聊天在工具验证为ok时挂载novel_tools和受控镜像，不依赖当前页面或显式Skill；没有项目或能力不足时显示纯文本能力，不能声称读写了项目。七个内置Skill见[resources/codex-skills](../resources/codex-skills)，安装不等于每轮显式注入。工具绑定版本为writing-tools-v11，旧工具契约不复用。verified reasoning effort随线程配置保留。路由切换须按活动任务守卫处理，任务范围解析与独立审查使用本次已选择的同一路由，不暗中换模型。

## 请求与任务范围

宿主先按自然请求识别操作、篇幅、编辑范围和审查义务。positiveInstructions处理否定范围；确定性解析是保守识别，不宣称理解任意自然语言。新篇幅请求使用原始上下限，容差0；旧持久化约束仍明确展示其容差。

进入项目工具回合前，宿主执行一次无工具只读的task_intent解析：只提供原请求、现有约束和资源目录/角色姓名，不生成正文。确定性预分类为unspecified也进入本次解析，由带用户原句依据的结果补全操作，再重新绑定相关义务；不能因请求不是“读取”开头就跳过。普通项目讨论也可能有一次范围解析，作者仍只有一次回合。输出的角色与资料ID必须属于当前小说，指定角色和视角必须引用实际用户原句（schema提供可选原文），人数与已有明确人数要求一致。指定参与集合与叙述视角在作者起稿前绑定；作者首次候选也不能把甲乙改成甲丙，或把指定有限视角改成全知。未指定的参与者/视角保留创作选择，不强制普通格式编辑补填视角。逐角色分别作答使用per_character，不伪造单一叙述焦点，也不误绑定为全知。

requiredReadResourceRefs是明确的资料集合，不以“每个类别读一份”替代“全部角色卡及各自记忆”。继续任务保留原请求、已绑定集合、原始记忆基线与问题记录；旧任务的reviewRequired在重新绑定时仍重新计算语义审查义务，不能因已绑定早退而绕过。范围解析是一次语义解释，界面展示结果及原句依据，不把它当作机器已证明完全理解用户。

task_intent阶段的停止会中止只读子调用，父任务保持interrupted；即使子调用在停止后返回有效结果，也不启动作者。原始请求在解析前写入运行记录，解析失败不能丢失任务诉求。

停止发生在资料目录加载或解析状态检查点期间时，不再派发范围解析模型请求。候选准备对资料交付、子执行启动及提交交接检查点逐次核对阶段revision与取消状态；初次检查点失败也释放取消控制器，后续记录失败不覆盖最初错误。

additionalContext包含novelId、resourceRef、baseHash、selection、nativeWorkspace、resourcePath和taskConstraints。宿主管理路径/版本；当前没有编辑器目标时可以为空，不能要求用户抄hash。限定selection/insertion必须核对项目、资源、版本、真实非空范围/光标；范围变更须重新选择。新章任务冻结既有章节集合，指定编辑目标不能改成其他资源或删整章。

## 资料上下文与记忆

read_writing_context一次读取任务绑定资料，返回sharedSources和逐角色actors。每个actor只组织该角色自己的卡片、当前主观记忆及任务前baselineMemory，不能合并成“全员已知”。这是给作者的信息归属结构，不宣称一个模型已实现安全隔离，也不以旧卡片的知识集合否定当前场景中新获知或正常内省。

返回内容均来自真实正式资源，拥有各自hash和读取区间；缺记忆明确exists:false，不伪造空内容。只有真实上下文工具的成功结果可扩展为读取凭证。编辑时绑定本任务读取版本，旧版/跨任务/不存在引文不能通融；元数据或捏造内容不能满足完整读取。写作任务的必读要求不能由随后只读审查的资料交付冒充作者已读。

写作输入读取与写后审查版本分开：资料被本任务修改后，宿主可用实际提交收据中的oldHash和完整读取内容证明写前已读；分页必须无缺口且完整内容hash一致，任意旧版本或片段不算。纯审校、当前正式资源读回及独立审查仍核对当前版本，不因写前已读而跳过。

memoryUpdateRequired与范围绑定分开，未绑定不能因必写集合为空而通过。用户指定参与者由宿主先绑定；未指定时作者候选通过participantCharacterRefs声明实际参与ID。宿主据此派生各自character-memory，不按项目总人数猜身份。明确同批要求时，正文和所有必写记忆必须在同一首次事务；最终核对宿主真实nativeItemId与批次资源。后续合法正文修订不强迫改写没有变化的记忆。

要求保留原记忆时，在任务开始冻结所有已有主观记忆。准备、批准及正式提交核对原有条目与字段，不能覆盖；本任务新条目可按实际读回ID修订。新增条目ID由宿主分配并在准备缓存中冻结。继续任务沿用原基线，不把已写出的结果重新当作原始事实。无法恢复的历史基线不能宣称已验证，详见缺陷清单。

## 原生补丁、批准与正式提交

1. list_novel_resources/read_novel_resource等只读工具返回真实资源标识、映射、内容和版本；分页只是传输范围。
2. syncNativeNovelWorkspace创建应用受控镜像。prepare_novel_patch是唯一候选生成入口：完整content、唯一精确replacements或memoryAppend，支持1—16个唯一资源；不写入正式小说、不批准、不做模糊匹配。同批任务可分步提交草稿，缺项返回draft_incomplete、draftOnly:true及preparationId，没有patch且preparedOnly:false；用该ID加changes显式组装，组装、修订及取回均保留同一草稿ID，禁止自动拼接无关联候选。同资源content替换暂存草稿；带ID的replacements编辑暂存内容，包含未保存新章；最初读取版本保持冻结。集齐正文和必写记忆后才返回preparedOnly:true及同一完整patch。候选材料保存在原chat-runs记录的writingPreparations中，取消十分钟TTL和八项进程缓存淘汰；更新增加revision，单纯取回不变，可用expectedRevision拒绝旧阶段。重启保留材料但停止旧任务、使旧批准失效，不自动重放草稿。
3. 既有资源绑定当前任务真实读取版本；新资源由宿主确认不存在并绑定absent。准备缓存冻结版本/ID，取回时重新校验；已有真实本任务提交时返回already_committed，不把重复取回误报成需要修补的版本错误。
4. 模型用Codex原生apply_patch编辑镜像相对路径。App Server请求宿主批准，默认展示具体差异。项目“新增正文”授权仅覆盖新章及完整保留旧文的章末追加，不覆盖改写、删除或结构化资料。
5. 批准前等待通知与提交队列；批准与fileChange完成分别核对路径、资源集合、操作和变更前后内容hash，再通过prepareChanges/applyPrepared正式提交。批准格式和完成格式可不同，但实际内容必须相同。符号链接、跨目录、越界或内容差异拒绝。
6. 非空apply_patch输出按LF结尾预测hash，所有资源类型一致，不裁剪原文规避校验。提交后更新镜像、真实读回、账本和资源通知；保存按每个批准事务发生，不等回合结束。

批准前持久化pendingNativeCommits；正式提交及检查点完成后清除。小说读取和预检等待提交屏障，超时/中断返回具体错误，不把旧正式资源或镜像中间态当保存结果。拒绝不保存；中断保留此前已提交部分。长patch只保留structuredContent一份，不在文本重复；同一exec准备后直接传给原生工具，避免输出截断和人工转抄。

### 阶段交接适配器的范围（2026-10-19）

[writingPreparationStage](../src/main/codex-runtime/writingPreparationStage.js)只衔接现有runOneShot、prepare_novel_patch与原生提交，不另建调度器、候选库、批准链或事务。preparationStage保存阶段位置、revision、原生执行引用和候选ID/revision；候选正文的权威材料在writingPreparations，详细过程沿用既有事件/账本。宿主和MCP更新原记录共用projectTransactions的跨进程读改写边界；宿主旧检查点不能覆盖MCP的候选材料。

候选阶段输入实际交付资料并记writingSourceDelivery，写入基线从这份输入快照绑定，不要求模型输出hash，也不悄悄采用后来版本。原生提交只取回冻结候选；批准前和实际提交前核对候选revision、实际差异、原始写入基线。记忆等JSON的原生LF文本与正式规范化内容分别核对，共用mutationService规范化器。正式提交读回完成时立即登记阶段结果，模型随后check_writing_task可见，不等回合结束才更新。提交执行器输出保留在执行记录；宿主根据当前正式收据展示标明来源的“保存回执”，只确认资源保存和实际字数，不将执行器是否知道事务结果作为保存证据。停止传递到只读子执行，子回合结束不释放父任务的项目归属。篇幅不足或超出仍允许按原规则批准保存草稿；字数只影响任务目标验收，界面显示实际字数及尚差/超出的字数，不将验收失败升级为保存权限错误，也不自动再次生成。版本、范围、原始记忆和事务校验继续执行。

当前适配器由隔离验收宿主接在原生作者首次派发前验证，**尚未自动路由普通聊天、传统写作或角色模式**。普通聊天仍沿现有单作者回合契约。此处验证原生衔接的可行性，不能据此宣称候选审查、角色隔离、定向修订或两模式整链已完成。原生apply_patch仍由模型发起；本轮本地协议没有提供可依赖的强制调用接口，未提交须如实保留未完成。

## 独立审查与问题生命周期

check_writing_task在保存后或纯审校时对当前冻结目标及必需依据执行一次无工具只读审查。协议v4返回reviews、issues、resolutions；宿主提供逐行引用ID及每份人物资料的所有者，仅发送一份可还原原文视图，并在宿主恢复实际位置/版本，模型不转抄hash、机器编号或行号。按目标与请求维度记录结论和限制；删除逐句分类槽、知识标签、全局时间证明表及其精确字节匹配硬门禁。单句也可构成问题依据，不要求凑两条引文。只读资料缺失/变化、畸形报告仍拒绝，不回退到作者自报空列表。

同一冻结资料包缓存一次结果，失败也缓存；实际修改后是新版本，需重新审查。范围解析、作者回合和独立审查分别记录用途/模型。宿主没有起稿失败自动恢复或为通过验收增加作者重试。每次用户发送只有一个作者原生turn，另有明确的task_intent与用户要求的独立审查调用，不再声称总共只有一个物理模型调用。

独立审查发布前核对原父run对象仍活动、未停止且未收尾，并在证据评估后再次核对正式资料版本。迟到成功、迟到失败和已停止宿主均不能写回父任务或发布完成事件；过期任务的临时审查文件清理。已经取消的审查调用不创建新队列项，资料交付先在局部快照评估，通过后才写入任务。

新问题issueId由宿主生成UUID，不根据模型提供的sourceKey或章节名推导；已有问题从宿主ID枚举选择。问题有稳定issueId、不可由换引文挪走的affectedResourceRefs及真实引文。evidenceVerified只表示引用/版本核验，不证明语义冲突成立。空报告、换严重度、替换为无关引文不能清除已知硬问题。只要求报告时可以交付发现；要求修复时，本任务相关open/hard使目标不完成。suspicion/偏好如实保留，不以引文数量自动升级为阻塞。

对既有问题明确选择unresolved、fixed或not_an_issue。同一ID不能同时未解决又关闭，状态冲突明确报错，不能生成重复问题行使整份报告无故失效。关闭已知问题须独立审查，作者自称fixed不生效。fixed需当前正式依据及changes指出原问题的哪项证据被实际修改；宿主用冻结原版本与当前版本的diff核对相应锚点确有改变，单纯加标题不算修复原句。这个检查证明编辑关联，不证明语义修复。not_an_issue也是独立模型重新判断，保留原因，不包装为确定性证明。相同已接受关闭可幂等复核，关闭依赖版本变化会重新打开。历史缺原版本快照时不能虚构fixed依据。

时间工具check_timeline_feasibility只核验传入明确数值，支持跨日、固定路程耗时及clockReadings实际/钟面读数和有符号偏差（快为正、慢为负）。不可解析或缺依据返回unknown；它不能证明已提取全文所有耗时，也不替代来源与视角判断。

## 完成状态、展示与恢复

执行终态、正式保存、任务目标和内容意见分开。wordCount仅按本次绑定的新章/目标及真实提交统计；旧书不能冒充新作。目标需满足必读、范围、篇幅、必写记忆、事务和审查义务。narrativeReview的reported/model_reported表示模型意见已记录，不是程序证明全文无错；不能把字段齐全或空issues等价于内容验收。完整结局的独立验收状态继续保留。

final_answer作为最终交付，commentary放入可展开过程。UI显示范围解析、独立审查、实际保存、缺项、硬问题和报告限制；不把部分保存显示成目标完成。无正式提交不能由模型回复“已保存”替代。

chat-runs保存检查点，文本定时持久化，批准/提交/终态立即保存。终态先持久化再发布；写失败保持finalizing只重试收尾，不重新执行模型或补丁。重载查询宿主；重启将旧活动状态标为interrupted，旧批准失效，保留已保存证据和继续目标。切项目/对话只改变显示，停止与批准始终绑定原runId。最终收尾及历史恢复不能覆盖用户后续编辑。


## 运行时恢复与确认重试（2026-10-19）

同一路由的 App Server 替换客户端后，线程驻留缓存与 Skill 初始化按客户端实例重新建立；恢复已有绑定线程，不自动重放执行结果不明的 turn。并发启动等待初始化握手，过期客户端的异步结果不能恢复旧驻留状态。

显式确认先完成决定账本、进度及检查点持久化，再安装批准并回应 App Server。持久化失败保留确认项，只允许重试同一决定；并发同决定共用一次操作，改变决定须停止任务。停止、退出与收尾先使待确认项失效，迟到 I/O 不得重新安装批准。当前工作区的 pendingNativeCommits 屏障和阶段拒绝状态继续保留在检查点边界；保存成功仍以正式事务及读回为准。

验证范围与未提交版本兼容性见[选择性合入记录](../artifacts/chat-chain-audit/report.md#运行时阻塞补丁选择性合入2026-10-19)。
