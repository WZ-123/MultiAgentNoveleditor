# 写小说主路径 UX 测试计划

最后更新：2026-05-10

## 目标

把“用户正常写小说”的主路径拆成可验证的体验步骤，再把步骤落成自动化用例，避免继续把低层 MCP 调用结果误当成用户体验测试。

## 正常体验流程

功能：打开一个已有小说项目，查看设定，编辑章节，向 AI 提问，并确认内容保存成功。

触发条件：用户启动应用，已有一个可写的小说项目。

操作路径：
1. 用户打开应用，当前小说项目被识别并同步到左侧章节树。
2. 用户在侧边栏看到章节列表和“小说数据”浏览器。
3. 用户展开角色卡或世界观，确认写作上下文存在。
4. 用户点击某一章，正文在中央编辑区打开。
5. 用户修改正文，应用自动保存到项目文件。
6. 用户在右侧 AI 聊天框输入问题并发送。
7. 系统至少应持久化用户消息；若 provider 可用，则继续返回 AI 回复；若 provider 不可用，则显示明确错误。
8. 用户重新打开项目后，章节树和刚才修改过的正文仍然存在。

退出条件：用户关闭项目或关闭应用。

成功状态：
- 章节树可见
- 数据浏览器可见
- 章节可打开并编辑
- 自动保存落盘
- 聊天输入可发送且消息被记录
- 重开项目后内容不丢失

失败状态：
- 项目已激活但 UI 未同步
- 章节树可见但无法打开章节
- 输入变更未落盘
- 聊天输入无法发送或消息未进入历史
- 重开项目后内容回退

## 测试用例

### T（正常流程）

T1. 项目激活后，章节树出现“第1章：星夜启程”，右侧聊天输入框可见。

T2. 点击章节后，中央编辑器加载正文内容。

T3. 展开“角色卡”和“世界观”，能看到角色名和世界观文本。

T4. 修改章节正文后，2 秒自动保存，磁盘文件包含新内容。

T5. 在 AI 聊天框输入并发送后，聊天历史中出现对应 user message。

T6. 关闭并重新打开同一项目后，章节树仍存在，章节正文仍包含刚才的修改。

### E（异常流程）

E1. provider 未配置时，发送聊天消息后不崩溃，user message 已落历史，UI 显示错误。

E2. 无活动项目时，左侧显示“未打开小说项目”，不应渲染脏章节树。

### B（边界条件）

B1. 快速切换小说数据标签时，不应出现旧异步结果覆盖新 tab 的崩溃。

B2. 聊天面板默认已打开时，测试不应先点切换按钮把面板关掉。

### S（状态转换）

S1. 章节编辑后保存状态应经历“编辑中 → 自动保存 → 已落盘/无错误”。

S2. 聊天发送后应经历“空闲 → 发送中/等待中 → 回复或错误”。
