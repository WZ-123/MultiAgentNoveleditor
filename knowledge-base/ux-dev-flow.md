# 交互式 UX 开发流程 Skill

## 概述

以人类交互视角（而非技术实现视角）驱动功能开发。先设计用户体验流程，设计测试用例，再通过自动捕获错误、修复、重测的循环，直到完全打通用户体验全流程。

## 适用范围

任何涉及 UI 交互的功能开发、修改、重构。不限于聊天功能。

## 七步流程

### Step 1: 需求分析 → UX 流程设计

以"用户操作路径"为主线，描述完整的用户体验流程：

**格式**：
```
功能: [功能名称]
触发条件: [用户如何进入此功能]
操作路径:
  1. 用户看到什么
  2. 用户做什么（点击/输入/拖拽...）
  3. 系统响应什么
  4. 用户看到什么变化
  ...
退出条件: [用户如何离开此功能]
成功状态: [功能正常时的最终 UI 状态]
失败状态: [功能异常时的 UI 状态]
```

**产出**：一份 UX 流程文档，包含每一步的预期 UI 状态。

### Step 2: 测试用例设计

在考虑边缘情况的前提下，按以下分类设计测试用例：

| 分类 | 说明 | 示例 |
|------|------|------|
| T (正常流程) | 用户按预期操作，全部成功 | 填写表单 → 提交 → 看到成功提示 |
| E (异常流程) | 操作过程中的错误和中断 | API 返回 500、网络断开、文件不存在 |
| B (边界条件) | 极端输入、空状态、并发操作 | 空列表、超长文本、快速重复点击 |
| S (状态转换) | 组件在 loading/empty/error/data 间的切换 | 加载中 → 空数据、加载中 → 错误 |

**每条用例包含**：
- 编号（T1, E1, B1, S1...）
- 操作步骤
- 预期结果
- 验证方式（视觉检查 / 控制台日志 / 网络请求）

### Step 3: 启动 Dev Server

启动开发环境，准备测试：

```bash
npm run dev
```

或项目对应的 dev 命令。

捕获终端初始输出，确认无编译错误和未捕获异常。

### Step 4: 执行交互测试

按 Step 2 设计的测试用例顺序执行：

1. 先测 T（正常流程）—— 主干不通则异常和边界没有意义
2. 再测 E（异常流程）
3. 再测 B（边界条件）
4. 最后测 S（状态转换）

**测试方法**：
- 打开浏览器开发者工具（Console / Network / Elements）
- 按用例步骤操作
- 观察 UI 是否符合预期
- 观察控制台是否有 error / warning
- 观察网络请求是否正常

### Step 5: 错误捕获

自动从以下来源捕获所有错误：

**来源 A — 浏览器控制台**：
通过 `mainWindow.webContents.executeJavaScript` 或手动检查 Console tab：
- `console.error(...)` 调用
- 未捕获的 Promise rejection
- 网络请求失败（4xx, 5xx, CORS, 超时）
- React 渲染错误（Error Boundary 捕获的）
- WebSocket 断连

**来源 B — 终端输出**：
- Vite/Webpack 编译错误
- Node.js 未捕获异常
- Electron 进程错误（`main.js` 中的 try/catch 未覆盖处）
- IPC 错误（`ipcMain.handle` 中抛出的异常）

**来源 C — React 组件内部**：
- state 异常（undefined 导致渲染崩溃）
- props 类型不匹配（object 当 string 渲染）
- 生命周期错误（useEffect 中未捕获的异常）

**错误记录格式**：
```
[来源] 文件:行号
错误信息: ...
上下文: 当前操作步骤
```

### Step 6: 修复循环

```
循环开始
  │
  ├─ 分析错误 → 定位根因
  │   ├─ 跟踪调用栈
  │   ├─ 检查数据流（IPC → handler → service → file）
  │   └─ 检查渲染流（state → component → DOM）
  │
  ├─ 修复代码
  │   ├─ 修改最少的代码
  │   ├─ 优先修复数据流问题（数据不对则 UI 一定不对）
  │   └─ 其次修复渲染问题（数据对了但显示不对）
  │
  ├─ 重启 Dev Server（如需要）
  │
  ├─ 重新执行测试
  │   ├─ 先重复失败用例（确认修复有效）
  │   └─ 再回归已通过用例（确认无副作用）
  │
  └─ 仍有错误？──→ 回到循环开始
       │
       否 → 进入验收
```

**关键原则**：
- **不能只看函数执行通过** — 必须验证 UI 控件真正加载和显示
- **追踪完整数据链路** — IPC → handler → service → file → React → DOM
- **一次只修一个问题** — 不要同时改多个不相关的代码
- **终端和 UI 的错误都要看** — 终端可能 silent fail，UI 可能报错但终端无输出

### Step 7: 验收

对照 Step 1 的 UX 流程文档逐条确认：

- [ ] UX 流程每一步的 UI 状态符合预期
- [ ] 所有 T 用例通过
- [ ] 所有 E 用例通过
- [ ] 所有 B 用例通过
- [ ] 所有 S 用例通过
- [ ] 浏览器控制台无 error / warning（已知且无害的除外）
- [ ] 终端无编译错误和未捕获异常
- [ ] 无新增的副作用/回归

## 技术栈适配

### Electron + Vite + React（本项目）
- Dev: `npm run dev`（concurrently 启动 Vite + Electron）
- 控制台检查: `mainWindow.webContents.executeJavaScript('console.log(...)')`
- 组件检查: React DevTools / Elements panel

### 通用适配
- Web 应用: 直接浏览器 DevTools
- React Native: Metro bundler + React DevTools
- 纯 Node.js: stdout/stderr 捕获
