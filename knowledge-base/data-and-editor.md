# 数据、资源与编辑器

来源：[paths](../src/main/store/paths.js)、[novels](../src/main/store/novels.js)、[novelData](../src/main/store/novelData.js)、[资源适配](../src/main/mcp/novelResources.js)、[镜像映射](../src/main/codex-runtime/nativeNovelWorkspace.js)。

## 两类目录

应用数据根由 `MANA_USER_DATA_ROOT` 或 Electron userData 决定，含模型配置、密钥存储、小说注册表、聊天记录、反馈 outbox、授权、进度及应用专属 codex-home。开发和测试不得默认指向用户正式数据。

小说项目根包含 `novel.json`、`chapters/`、`summaries/`、`characters/`、`factions/`、`world/`、`timeline/`、`outlines/`、`assets/`、`style/` 与 `.mana/`。具体位置只由 `novelPaths` 和业务存储函数决定，不从显示名称拼接任意路径。

## 资源不是任意文件路径

| 资源标识示例 | 原生镜像路径 | 注意事项 |
| --- | --- | --- |
| `novel:meta` | `novel/meta.json` | 正式元数据是项目根 novel.json |
| `chapter:chapter-001.md` | `chapters/chapter-001.md` | 章节名称需要校验 |
| `character:alice` | `characters/alice.json` | 结构化 JSON |
| `world:lore` | `world/lore.md` | 世界观文本 |
| `timeline:all` | `timeline/events.json` | 正式目录使用 events.jsonl |
| `outline:master` | `outlines/master.md` | 不等于正式存储文件名 |
| `outline:chapter:1:2:3` | `outlines/chapter-v001-s002-c003.md` | 正式存储有层级目录 |
| `style:memory` | `style/memory.md` | 文风资料 |

完整支持范围以双向映射函数为准，不是目录内所有文件都能由模型编辑。时间线镜像同步跳过单事件描述符，不能假定每个可读资源都已生成独立镜像文件。路径逃逸、符号链接和重复映射必须拒绝。

## 手工编辑与 AI 编辑是两个入口

手工章节编辑经 App 的保存队列和 `novel.saveChapter` 落盘，使用基线处理冲突；AI 编辑经原生镜像、批准、mutationService 落盘。两者共享正式资源，但不能互相覆盖未处理的版本冲突。

渲染层正文保存按项目 ID 与文件名串行执行；普通后续保存使用上一成功提交的基线，显式 AI/冲突处理基线不自动放宽。保存回执只更新已提交基线；若期间有新输入，保留当前正文与脏标记。自动保存计时器同样按项目和文件隔离；切项目先排空当前草稿，失败保留当前界面。历史恢复与标题保存进入同一队列。

项目切换器在宿主 open/close 前等待上述保存，失败时宿主与编辑器均保留原项目。结构保存失败不会清除未完成记录；再次切换时重试当前树，成功后才继续，避免丢失空卷或空节。外部客户端切换以及无 novelId 的历史章节通知不在此守卫的验收范围。

`novel.json` 的 structure v2 保存稳定卷/节 ID 和各节 chapterFiles；恢复按文件名分配且每个文件只出现一次，保留空卷/节。旧数据只用有效数字位置补回未映射章节，无法判断归属的旧章节放入“未分组章节”，不按文件切片猜测。新章同时保存数字卷/节 frontmatter 和结构映射。

聊天发送前按绑定资源调用 `flushActiveChapterToDisk`，保存失败保留草稿并显示错误，不启动模型。编辑器菜单命令先保存，再绑定目标资源、版本和显式范围；切章不替换目标，版本变化要求重新选择。编辑器的普通选区只提供上下文，不当作修改授权。

提交事件由 `ipc/codex` 广播；App、数据面板和章节事件订阅刷新受影响内容。刷新按 committedResources 的项目与资源类型路由，不依赖工具名称。资料页正在编辑时保留草稿、提示冲突并阻止覆盖；取消编辑后重新读取正式资源。章节同步也保留脏稿。收到事件只证明需要刷新，仍需验证正式读回结果。

## 存储事务与审阅契约

本轮不可变审阅身份约束：候选创建时将每个集合实体绑定为内部 operationId，并保存该操作的原实体、原基线身份和候选身份。已有 ID 或唯一名称只用于首次匹配旧基线，不能在字段应用过程中重新计算定位；名称修改不改变 operationId。旧待审记录升级只使用其保存的基线与候选。出现歧义时停止，不能按当前数组下标或名称猜测。领域文件不需要写入用于审阅的临时 ID。

已有 JSON 根和已有集合实体从完整原值构造结果，仅应用明确批准的字段；候选的默认值、缺失字段和额外属性不能变成删除或新增授权。新实体才使用候选作为初始对象。网页补全的 _enrichmentRunId 从持久 review.runId 写入可信来源元数据，不通过候选字段隐式透传。

已有项目合并也将完整资源计划和不可变目标身份存入运行 commitDecision。session 的选择、摘要和回执为执行材料；恢复从权威计划执行，并验证具名事务的真实提交证明，不能相信被改写的 session receipt。登记迁移与执行按同一 novelId 身份租约串行；运行、材料与领域文件的详细转换规则见 [导入命令契约](import-and-merge.md#唯一状态权威与命令转换2026-10-19-重做契约)。

[projectTransactions](../src/main/store/projectTransactions.js) 是本次数据导入与普通领域保存共用的文件提交层；[resourcePlan](../src/main/import/resourcePlan.js) 仅转换审阅文件计划，不再拥有另一把写入锁。普通领域 API 在同一可重入项目事务内读取、修改和保存，底层 atomicWriteFile、JSON、文件 IPC 的项目写入接入同一协调器。锁按真实项目路径归一，进程内排队与磁盘锁共同串行化合作写入方。

`.mana/transactions/` 在每次尝试写入前记录 intent，写后读回再记 applied；事务完成才记 committed。失败或下次进程访问时，只逆序恢复该事务已经登记的写入意图，不能遍历整份未执行计划。目标是原字节时无需恢复，是本意图的后字节时恢复原值，出现第三种字节则停止并返回 recovery_required。二进制以 base64 保存恢复字节；终结的普通保存临时日志清理，具名批量提交保留幂等回执。任意外部编辑器不参与项目锁；遇到其修改不能假定拥有写入权。

[reviewStore](../src/main/import/reviewStore.js) 在 `.mana/reviews/` 保存分析、重建、网页补全的候选、来源、原始基线和逐项决定。状态为 review、committed 或 cancelled；写入中的状态属于存储日志，不在 UI 再维护另一套 committing 状态。未决定的事实不得提交；确认后，领域字节、审阅终态、回执及角色索引处于同一存储事务。候选断言不留在正式字段中充当默认事实，完整候选保存在审阅记录，正式数据通过 _factReviewId 关联来源。项目提升复制封闭审阅记录并重绑定目标项目，同时保留 sourceRoot；不复制旧项目的锁与活动恢复日志。

[reviewOperations](../src/main/import/reviewOperations.js) 在创建审阅时，用稳定 ID 或旧项唯一名称首次匹配捕获基线，再持久绑定内部 operationId、完整原实体和字段原值。应用字段前为 operationId 建立固定槽位，名称修改不会改变后续字段的定位；不在变化中的对象上重新计算身份。拒绝已有身份恢复完整原实体，拒绝已有字段保留原值，拒绝新增身份不创建；未提及旧项不代表授权删除。旧 schema 1 审阅也仅从其保存基线升级。地点基线以 places.json 为准；未确认正文相关字段变化时保留 lore.md 原字节。领域文件不注入临时审阅 ID。

[promotionTransactions](../src/main/import/promotionTransactions.js) 是跨目录提升执行器。`ImportRunStore` 中的 commitDecision 是唯一业务提交决定，内含 operation ID、import ID、正式 ID、目标、manifest 和原回执；提升 state.json 仅是物理执行检查点。执行器先准备 owner/manifest 和持久目标保留，再由运行命令裁决提交或取消。决定之前可取消；决定之后只能核对归属并续交目录、登记与回执。取消通知文件仅供观察，不授予或撤回提交权。物理检查点落后于 run 时，使用权威决定中的计划续交。损坏记录、未归属目录、第三种资源字节、清单外新增文件或已移到其他目录的登记身份阻止未发布产物恢复，不覆盖现场。正式目标不得与暂存来源重叠。

正式小说登记与 importPromotionReceipt 同一次原子保存。尚未登记的产物必须逐资源核对 manifest；若登记中已存在与本次操作完全匹配的回执，该回执证明原数据已正式发布，后来的正常编辑属于新版本。恢复只核对目录/正式身份/原 manifest 归属并完成收尾，不重放旧正文，也不把后续编辑误判为未提交产物。普通“重新定位已移动项目”仍保留原行为；提升恢复专门禁止静默改动已登记到其他目录的身份。

共同协调器的 exclusive 租约用于多步业务协议，各步骤仍通过其事务日志持久化；后续步骤失败不会撤销已经持久化的提交决定。租约和事务权限随当前调用结束失效，迟到异步回调必须重新排队。小说与暂存登记的读改写共用应用数据根租约；提升准备释放源项目锁后才进入正式登记，避免相反锁序。运行记录读取先恢复其存储日志，不能把尚未提交的终态当作已完成。

取消与提交决定共用运行命令租约；目标保留之后的 decideCommit 必须重读 run 并验证工作 token，不能留下“先查取消、再异步决定”的窗口。进入协调器时先登记调用方路径别名，再按真实目录加锁，保证已登记父目录不会接管子目录的首次写入及日志。

原生写作的 [mutationService](../src/main/mcp/mutationService.js) 仍负责其批准、资源版本和逻辑事务；本次未改写主线写作链。其调用领域存储或 atomicWriteFile 的写入服从共同文件边界；不能据此宣称主线批准、连续写作或角色记忆的新实现已验收。主线相关约束与证据仍以运行契约和主线审计为准。

验收覆盖同资源并发、旧版本、身份升级、拒绝、写入失败、进程退出后的恢复、第三种版本阻止恢复、跨进程取舍读取和完整 UI 正式读回；实际覆盖及限制见 [审计报告](../artifacts/data-import-safety-audit/report.md)。

## 角色身份与离线记录补修（2026-10-19，独立树）

角色卡 ID 拒绝路径段和控制字符；保留合法特殊身份，磁盘不便直接表示的 ID 使用 SHA-256 文件表示，不通过有损清洗合并身份。读取/写入拒绝符号链接，检测 NFKC/大小写文件名碰撞。读取和 CAS 使用同一个逻辑身份解析结果；保存时将旧特殊文件名与新文件表示放入同一事务迁移，保留角色记忆，已存在多个同 ID 文件时明确报歧义而不任取一个。模型重复 ID 在准备阶段分配独立 ID，同时用于 JSON 身份和文件名。此项只改角色卡；角色记忆格式的主线补修须在集成时单独保留。

本机离线编辑仍即时正式保存，离线记录是已保存操作的审计记录；恢复联网只确认记录，不再次覆盖正文。真正待提交的操作要求完整变更、目标身份及基线，在共同项目事务内调用领域 API 保存，具名日志保留该离线项的幂等回执；不进入独立写作队列，也不以“当前恰好等于候选”猜测已经执行。重复请求返回原回执。界面预览完整载荷，区分仅确认和实际写入，失败仍保留记录。旧版无保存证明的摘要不得回放；不支持或缺数据的动作报错并留待处理。存储配额不能删除待确认/待提交记录。详见 [审计报告](../artifacts/data-import-safety-audit/report.md)。
