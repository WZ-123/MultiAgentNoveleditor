# 角色联网补全

来源：[角色 UI](../src/components/CharacterEnrichPanel.jsx)、[资格校验](../src/main/import/characterEnrichmentEligibility.js)、[补全实现](../src/main/import/characterEnricher.js)、[导入 IPC](../src/main/ipc/import.js)。

## 职责

补全二创角色的原作资料，保留用户创作资料与来源证据。明确标记 `isOriginal === false` 的角色才满足资格检查；未知状态不能自动解释成二创。原作信息缺失时不能自行把同名角色合并到某作品。

当前实现根据原作识别文化圈、选择搜索语言和来源，批次内缓存搜索；并发数从配置读取。原创角色跳过。搜索与抓取由应用业务代码完成，网页资料的模型提取通过 `mana-import-enrichment` 和 nativeProvider 进入原生 Codex 服务。

## 数据过程

1. 检查二创资格及原作信息。
2. 依据 [搜索路由](search-routing.md) 定位角色页面，排除列表页和同名误命中。
3. 解析页面、必要时补抓相关页面；模型只对得到的资料做提取。
4. 校验角色/原作匹配、字段在页面中的依据及完整性；必要时使用其他来源补充。
5. 三方合并后持久准备候选，用户确认网页主体/原作并逐项选择或拒绝字段，调用共同事务保存到绑定的暂存或正式项目。

搜索命中、网页成功返回、字段提取、合并和正式保存是不同结果。无证据字段不得用模型常识补齐后冒充网页事实。批次部分失败应保留角色级结果，不能把每个角色都显示为成功。

## 验收重点

原创/资格未知、原作缺失、日文/英文原名、同名人物、目录页误命中、页面正文不足、联网超时、单角色失败、多角色并发、重复补全、用户编辑保留、切换项目和取消后的迟到结果。

历史实验的成功数量不作为当前承诺。搜索策略的唯一说明在搜索路由文档，本页不复制一份来源排序。

## 安全保存与未知信息（2026-10-19，独立树）

补全入口具备有界并发、取消和单角色失败隔离。抓取页标题需指向目标角色，正文介绍部分需提及作品；仅出现在其他人物页的相关条目不具备候选资格。这仍只是进入审阅的条件，不是页面身份或事实语义已经验证。

逐字引文存在与语义支持分开保存。与引文相反的改写不能变成自动通过的正式字段；有引文的模型改写作为未确认候选保留，供用户核对，而不是删除改写功能。身份与字段均需明确决定。完整来源、引文、候选和决定保存在审阅记录；正式卡只包含经裁决的值与记录引用。未知字段不从萌点或模型常识补齐。补全完整性另行记录，部分结果不显示为已完整保存。

联网前快照、候选与当前角色三方合并，保留期间用户修改和删除。准备过程在共同项目事务内绑定实际版本；审阅期间再修改会阻止提交，需要重新准备，不能自动放宽基线。提取结束显示待审阅；只有审阅提交并正式读回后才显示 reviewed。已抓取的页面与补页在有界请求中完整分片处理，保留成功片段的候选并明确标注失败片段；不再静默截掉已拿到的页面尾部。网页事实的语义裁决由用户承担，不能把字符串匹配当作自动事实核验。

重新生成先完整提取、验证并持久准备候选，逐字段审阅与整批拒绝使用同一审阅存储。源卡集合和版本均被检查；失败、空输出、畸形身份和拒绝保留旧卡，新增旧卡也会使整批版本过期。旧 ID 与记忆保留，成功后同事务重建索引。页面重开从持久记录恢复。

保存与恢复规则见 [存储事务与审阅契约](data-and-editor.md#存储事务与审阅契约)。

验证分层及限制见 [审计报告](../artifacts/data-import-safety-audit/report.md)。
